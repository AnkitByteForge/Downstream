ADR-006.md

MCA and FLA are represented as explicit, nullable, first-class engineering
fields on `SubmittalRevision`, not as part of a generic electrical-properties
or equipment-characteristics framework.

Reason:

Canonical_Demo_Dataset.md defines SUB-118 with **both** values per revision and
per revision only:

    Rev 0: MCA = 180 A  |  FLA = 150 A
    Rev 1: MCA = 240 A  |  FLA = 200 A

The canonical document itself states these live "on `SubmittalRevision`" and
are "fields, not a new entity type any source names" — the Fidelity Review's
own framing treats PO-relevant equipment values (tag/mark, model/manufacturer,
capacity/size) as flat fields, not a sub-entity. RES-3 implemented MCA via the
existing `capacity_value`/`capacity_unit` pair but silently dropped FLA at the
domain boundary.

Adding a generic property-bag / electrical-characteristics framework would
contradict that "fields, not an entity" directive and introduce a mechanism no
frozen source names. The smallest domain-faithful representation is a scalar
pair on the revision mirroring the existing capacity pair:

    fla_value: float | None
    fla_unit:  str | None

They are nullable so non-electrical submittals and revisions where FLA is
unknown remain valid (backward compatible with existing rows).

Implementation: `SubmittalRevision` gains `fla_value`/`fla_unit`; propagated
through the ORM model, Alembic migration 0011, repository mapping, API schema,
seed data (Rev 0 = 150 A, Rev 1 = 200 A), and the frontend type + Submittal
detail UI.
