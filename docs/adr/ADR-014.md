ADR-014.md

`PurchaseOrder.status` is a normalized 10-value superset —
`DRAFT, PENDING_APPROVAL, OPEN, PENDING_CHANGE_APPROVAL, ON_HOLD, CLOSED,
FINALLY_CLOSED, CANCELED, REJECTED, WITHDRAWN` — rather than a literal
reproduction of Oracle Fusion's 15 documented header statuses or SAP's
release-indicator-plus-flags model. `acknowledged`, `delivery_completed`,
and `final_invoice` are modeled as boolean flags on the entity, not as
separate statuses.

Reason:

The Reference Commercial System.md itself licenses this explicitly in its
own Caveats: "Naming and enums are partly configurable, not universal...
the model should treat state names as a normalized superset, not a copy of
any one vendor." Oracle's 15 statuses (`Closed for Invoicing`, `Closed for
Receiving`, `Pending Signature`, `Sent for Signature`, `Incomplete`, etc.)
and SAP's release-indicator/flag combination describe the same underlying
lifecycle through different vendor-specific vocabularies. Folding
`acknowledged`/`delivery_completed`/`final_invoice` into boolean flags
rather than three-way-branching statuses matches SAP's own literal
approach (the Delivery Completed Indicator `ELIKZ` and Final Invoice
Indicator are documented SAP flags, not statuses) and is the simpler,
equally-expressive shape.

**Transition set exercised in CS-1**
(`domain/state_machines/purchase_order_transitions.py`): `submit_for_approval`,
`approve`, `reject`, `withdraw`, `cancel`, `acknowledge`, `hold`,
`release_hold`, `amend`, `approve_amendment`, `close`, `finally_close` — a
complete, tested state machine, not a partial one; every legal and every
illegal transition has a unit test.

Consequences:

- A future adapter mapping this system's `status` onto a real SAP/Oracle
  tenant's native vocabulary performs that translation in its own
  `mapper/` layer (per `04_Downstream_Connector_Layer_Validation.md`'s own
  "envelope construction lives entirely inside each Connector adapter"
  rule) — this system's status values are never assumed to be a real
  vendor's literal wire values.
- `changed_at` is stamped on every transition (not only on header field
  edits), so the `changed_since` polling-fallback query
  (`04_Downstream_Connector_Layer_Validation.md`'s SAP/Oracle finding that
  native event push is often absent) reflects lifecycle changes honestly.
