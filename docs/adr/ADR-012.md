ADR-012.md

`OrgScope` (company_code, plant, purchasing_org, business_unit) is
embedded as plain nullable columns on every scoped table (`purchase_orders`,
`vendor_scope_views`, `cost_codes`, `commitments`, `contracts`), not stored
in a separate joined table. Two distinct company codes are seeded
deliberately in CS-1 (`"1000"`/`"P100"` for Scenario A, `"2000"`/`"P200"`
for Scenario B), so org-scope isolation is a real, testable property from
the first commit rather than an assumption.

Reason:

The Reference Commercial System.md §L: SAP's Client -> Company Code ->
Purchasing Organization -> Plant -> Storage Location and Oracle's Business
Unit are real visibility-constraining dimensions, not decoration — "a PO in
Plant A is not automatically visible to Plant B." Embedding as columns
(rather than a joined `org_scopes` table with a foreign key from every
scoped entity) is the simpler, equally-correct shape at this system's
scale — the same "correct and simple, not a fidelity loss" judgment RES-2
already made for in-memory pagination and RES-5/ADR-008 made for
predecessor/successor edges.

**Company codes are an inferred seed choice, not a literal frozen value.**
`docs/05_Downstream_Reference_Execution_Trace.md` Phase 12.2 states
Scenario A's company code (`"1000"`) and plant (`"P100"`) literally.
`Canonical_Demo_Dataset.md` states no company code/plant for Scenario B at
all. Assigning Scenario B a second, distinct scope (`"2000"`/`"P200"`) is
this system's own inferred judgment call, made explicitly (not silently)
so ADR-015's org-scope isolation guarantee has two real scopes to
distinguish rather than one — recorded here rather than picked without
comment, per the same discipline `ADR-008` used for `ScheduleActivity.type`.

**On PO-number-collision testing, explicitly not attempted.** The approved
plan's own risk-mitigation note (§26 item, "overlapping PO-number ranges")
anticipated seeding two identical PO numbers under different company codes
to prove numeric uniqueness is not assumed globally. This was **not**
done: `Canonical_Demo_Dataset.md` §10 states each scenario's PO numbers as
frozen literal values (`"4500018823"`, `"4500019104"`, `"4500020045"`,
`"4500020091"`), all distinct. Inventing a duplicate would violate the
standing "do not invent data not grounded in the frozen documents"
instruction. Org-scope isolation is instead verified by contract tests
that filter by `company_code` and assert cross-scope invisibility for an
integration client scoped to one company code — a materially equivalent
guarantee, achieved honestly rather than through fabricated collision data.
