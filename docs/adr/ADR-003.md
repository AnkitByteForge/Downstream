ADR-003.md

Submittal review-status vocabulary is configuration-driven, not a closed enum.

Reason:

The Enterprise Fidelity Review documents that real systems (Procore) offer nine
default submittal responses and allow up to twelve custom responses on six of
eight configurable defaults — the vocabulary is a per-project/per-company
configuration, not a fixed set. RFI.status and DrawingVersion.status remain
closed Python-level enums, since neither the frozen Reference Engineering
System spec nor the Fidelity Review calls for their configurability — only
Submittal's status vocabulary is singled out.

Implementation: a seeded `submittal_review_statuses` table
(project_id, code, label, gates_procurement, is_terminal, sort_order),
referenced by SubmittalRevision.review_status_id. The domain state machine
still enforces a fixed set of *transition shapes* (prepare → submit →
disposition); only the *labels* available at the disposition step are
configuration-driven, read from this table rather than hardcoded.
