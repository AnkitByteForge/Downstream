ADR-010.md

The Reference Commercial System is a full, independent reference
enterprise application — a real FastAPI/Postgres backend (and, from CS-7
onward, a real Next.js frontend) — not a mock, not a fake JSON API, and
not a Downstream service.

Reason:

Extends ADR-001's precedent ("Reference Engineering System includes a web
UI") explicitly to the commercial side, per the approved Commercial System
Implementation Plan v1 §0. The system plays the role a real SAP/Oracle/
ERPNext tenant would play against a future `connector-sap` — it must be
something Downstream connects *into*, with its own persisted state and
lifecycle, not a canned response generator.

**Renumbering note, recorded rather than silently resolved:** the approved
plan (approved before this ADR was written) proposed this decision as
ADR-009. Between plan approval and CS-1 implementation, `docs/adr/ADR-009.md`
was independently claimed by concurrent Reference Engineering System work
(the DIP -> Engineering Evidence Promotion milestone's OAuth2
`client_credentials` grant and `RevisionCloud.source_evidence_ref` field).
Every ADR number in the approved plan (originally 009-015) is shifted by
one to 010-017. This file and its siblings are the authoritative numbering;
the plan's own §25 table is now stale on numbers only, not on content.

**Frontend timing.** CS-1 (this milestone) builds backend only — domain,
application, infrastructure, API, migrations, seed, tests — per the
explicit CS-1 authorization ("Do NOT build the frontend yet unless the
approved CS-1 scope explicitly requires it"; it does not). The frontend is
CS-7. This ADR records the eventual-UI decision now, matching how ADR-001
was recorded before RES-1's frontend code existed, so the decision is not
silently assumed later.
