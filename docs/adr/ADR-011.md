ADR-011.md

Every reference from the Reference Commercial System to the Reference
Engineering System (spec sections, cost codes, schedule activities, RFI/
DesignChange trigger identifiers) is a plain string business key, never a
foreign key, never a shared database, never imported code.

Reason:

This is the load-bearing independence guarantee the user's implementation
authorization states explicitly: "no shared database and no cross-system
foreign keys... cross-system references use stable business keys only."
The two systems are, and must remain, separately deployable services with
separately owned Postgres instances — exactly the posture the Reference
Engineering System itself already has toward Downstream (`docs/03`'s
storage-boundaries table: a connector's origin system remains the only
place raw truth lives; everything else is a pointer).

Concretely, in CS-1: `CostCode.standard_ref` is a bare string (e.g.
`"23 31 13"`), matched only by value against RES's `SpecSection.number` —
never joined in SQL, never validated against RES at write time.
`POScheduleLine.linked_schedule_activity_ref` (CS-3 field, declared now on
the entity for schema completeness) is the same pattern, pointing at RES's
`ScheduleActivity.activity_code` (e.g. `"3410"`). Vendor name continuity
(`"Arjun Steelworks"`) is preserved by spelling, not by any database
relationship — a human or a future Downstream Key Resolution service
reconciles these by string equality, never by FK traversal.

The Reference Commercial System's own `backend/pyproject.toml` declares no
dependency on `packages/*`, `reference-engineering-system`, or any other
part of this repository's code. Its migrations, ORM models, and domain
entities are self-contained.

Consequences:

- Every cross-system field in CS-1's schema (`CostCode.standard_ref`) is a
  nullable `VARCHAR`, never a `ForeignKey(...)`.
- A future Downstream `artifact_identity_map` (already specified in
  `07_Downstream_Implementation_Blueprint.md` §6) is the only place either
  system's identity is ever mapped to the other's — not this system's job,
  not RES's job.
- The two systems can be migrated, seeded, restarted, or torn down fully
  independently, and were verified as such (see the CS-1 completion
  report: `reference-commercial-system` was brought up, migrated, and
  seeded from an empty database with the Reference Engineering System's
  own containers never started).
