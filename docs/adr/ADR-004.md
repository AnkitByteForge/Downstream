ADR-004.md

Submittal is modeled as a parent (Submittal) + child (SubmittalRevision) pair,
mirroring the existing Drawing / DrawingVersion pattern.

Reason:

The Reference Engineering System.md's own synthesized entity list depicts
Submittal as one flat entity with a scalar `rev` field. That shape cannot
support Downstream Intelligence Specification §13's canonical demo
walkthrough, which requires diffing "the current submittal's equipment
schedule against the prior revision" — a scalar field cannot hold two
revisions' values at once.

The parent+child split is not a new domain concept; it is the same pattern
the frozen document already uses for Drawing/DrawingVersion, applied to the
one other entity whose own field list already implies revision history.

Implementation: `Submittal` holds envelope-level fields that do not change
across revisions (project, spec_section, package, vendor, commitment,
number, lead_time_days, required_on_site_date). `SubmittalRevision` holds
everything that changes per revision (review_status, ball_in_court,
equipment_tag/manufacturer/model/capacity, submitted_at, disposition_at,
and its own drawing/location references) — mirroring exactly how
DrawingVersion holds revision_clouds and location_ids while Drawing holds
sheet_number and discipline_code.
