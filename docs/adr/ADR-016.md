ADR-016.md

Currency is an explicit field on `PurchaseOrder`, `Commitment`, and
`Contract`. Scenario A's seed rows (`po_4471`, `po_4488`, `po_4512`) are
denominated in INR, matching `05_Downstream_Reference_Execution_Trace.md`'s
frozen figures verbatim and unconverted. Scenario B's seed rows (`po_5201`,
`po_5202`) are denominated in USD, matching `Canonical_Demo_Dataset.md`
§10's own sourcing from the Enterprise Fidelity Review's Wood Mackenzie /
switchgear-pricing figures, also verbatim and unconverted. No use case,
endpoint, or seed script ever sums or otherwise aggregates a value across
the two scenarios' currencies.

Reason:

This was the one open item the approved Commercial System Implementation
Plan v1 could not resolve on its own (`Canonical_Demo_Dataset.md` §22 item
2, never answered until CS-1's authorization). The user's implementation
authorization resolved it explicitly as a "Mixed" convention: "Scenario A:
INR, preserving the frozen figures verbatim. Scenario B: USD, preserving
the canonical Scenario B figures. Never perform cross-scenario currency
aggregation." This ADR records that resolution as the binding decision for
all of CS-1 and every later milestone that reads this seed data.

Consequences:

- Every monetary API response includes its own `currency` field; no
  endpoint returns a bare number without it.
- A future portfolio-level rollup (explicitly out of CS-1's and, per the
  approved plan, out of every milestone through CS-8) must perform its own
  currency conversion before aggregating — this system does not do that
  conversion itself, and none of CS-1's seed or test code assumes one
  currency project-wide.
